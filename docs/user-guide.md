# 사용자 가이드

AFP Designer로 후보를 설계하고 실험할 서열을 고르는 방법이다. 앱은 `python -m streamlit run app/Home.py`로 실행한다.

> **먼저 읽을 것:** 모든 점수는 우선순위 보조 지표이며 실제 열이력(TH)이나 얼음 재결정 억제(IRI) 활성을 예측하지 않는다. 점수가 높은 후보가 활성이 있다는 뜻이 아니다. 결과는 실험으로 확인해야 한다.

## 시나리오 1: 기존 AFP를 개선한 후보 만들기

1. **홈**에서 **시드 AFP**를 고른다(예: Type III HPLC-12). 시드의 IBS 잔기와 근거 수준이 표시된다. 근거 수준이 "문헌 확인"이 아니면 노란 경고가 뜬다. 잔기 목록이 불완전할 수 있다는 뜻이다.
2. **설계 파라미터**를 정한다.
   - 후보 수: 처음에는 20~50개로 시험하는 것을 권한다. 이 PC처럼 ESMFold를 CPU로 돌리면 후보당 10~20초가 걸린다.
   - 최대 변이 수: 후보마다 1~N개를 치환한다. 값이 클수록 시드에서 멀어지고 구조가 틀어질 위험이 커진다.
   - IBS 근처 반경: IBS 잔기에서 이 거리 안의 잔기는 성질이 비슷한 아미노산으로만 바꾼다.
   - 온도: 낮을수록 ESM-2가 선호하는 변이 위주로 뽑는다.
3. **실행**을 누른다. 작업은 별도 프로세스로 돌기 때문에 화면이 멈추지 않는다. 진행률, 단계, 로그가 표시되고 **취소**할 수 있다.
4. 완료되면 **순위표 보기**를 누른다.

### 순위표 읽기

- 점수는 네 그룹의 가중합이다: 구조 신뢰도(pLDDT, 시드 대비 RMSD), IBS 품질, AFP 유사도(ESM-2 로그비와 서열 동일도), 개발성.
- 왼쪽 **가중치 슬라이더**를 움직이면 순위가 즉시 바뀐다. 구조 신뢰도만 보고 싶으면 나머지를 0으로 둔다.
- **필터:** pLDDT 최소, 시드 대비 RMSD 최대, 거의 같은 서열(near_duplicate) 숨김, 개발성 플래그 후보 숨김.
- **플래그:**

| 플래그 | 뜻 |
| --- | --- |
| `low_ibs_confidence` | IBS 영역 pLDDT가 임계값보다 낮다. IBS 지표를 믿기 어렵다 |
| `qc_failed` | 구조 예측에 실패했다 (점수 없음, 순위 맨 뒤) |
| `n_glyc` | 시드에 없던 N-글리코실화 서열(N-X-S/T)이 생겼다 (진핵 숙주에서 문제) |
| `odd_cys` | Cys 개수가 시드와 다르다 (모드 A는 Cys를 바꾸지 않으므로 드묾) |
| `hydrophobic_patch` | 노출된 소수성 표면이 시드보다 10%p 이상 늘었다 (응집 위험) |
| `near_duplicate` | 순위가 더 높은 후보와 서열 동일도가 97% 이상이다 |

- **IBS 지표**(평면성, 면적, 격자 편차, 소수성 비율)는 시드의 IBS와 같은 크기 무작위 표면 패치를 기준으로 정규화한다. 양성 대조 검증에서 평면성은 시드와 무작위 패치를 일관되게 구분했지만 나머지 지표는 그렇지 않았다. 점수의 IBS 그룹은 참고로만 보고, 필요하면 가중치를 낮춘다. 모드 A는 IBS 잔기를 바꾸지 않으므로 후보 사이의 IBS 지표 차이는 작을 수 있다.
- 점수 정의와 기준값은 **점수 정의와 기준값** 펼침 영역에서 볼 수 있다.

### 3D 비교

표에서 행을 1~4개 선택하면 시드(회색)와 후보(색)를 Cα 기준으로 겹쳐 보여준다. IBS 잔기는 스틱으로 강조된다. 3D 뷰어는 인터넷에서 3Dmol 라이브러리를 불러오므로 오프라인 환경에서는 동작하지 않는다.

### 내보내기

표에서 후보를 선택하거나(선택이 없으면 현재 표의 상위 후보) **내보내기**를 누른다. 폴더에 다음이 만들어지고 ZIP으로 내려받을 수 있다.

- `candidates.fasta`: 첫 항목이 **시드 원본**(실험 양성 대조군), 이어서 후보. 헤더는 `>후보ID|변이|score=|rank=`이며 변이 번호는 시드 서열의 1-based 인덱스다(문헌 번호와 다를 수 있음).
- `ranking.csv`, `structures/*.pdb`, `seed.json`, `params.json`, `versions.json`, `scoring.json`, `README.txt`

## 시나리오 2: 새 시드 등록

1. 홈의 **새 시드 등록**을 연다.
2. 시드 ID(영문·숫자·_·-), 이름, PDB 또는 FASTA 파일, IBS 잔기 번호(예: `9, 14, 15-18`)를 입력한다. PDB 체인을 비우면 첫 체인을 쓴다.
   - **PDB:** 실험 구조를 그대로 시드로 저장한다. IBS 번호는 PDB의 잔기 번호다.
   - **FASTA:** ESMFold로 구조를 예측해 시드로 저장한다(CPU에서는 수십 초에서 수 분). 이때 IBS 번호는 서열 위치(1부터)다.
3. 등록되면 페이지를 새로고침해 시드 목록에서 고르고 시나리오 1과 같이 진행한다. 사용자가 올린 시드의 근거 수준은 "사용자 입력"으로 표시되며, IBS 잔기의 근거는 사용자 책임이다.

## 실행 이력 페이지

- 모든 실행의 상태, 진행률, 파라미터, 도구 버전, 로그를 본다.
- **같은 설정으로 재실행**하면 같은 서열이 재현된다(난수 시드가 같으면).
- pLDDT와 RMSD 임계값을 바꿔 구조 QC를 통과한 후보 수를 확인할 수 있다.

## 자주 묻는 질문

- **후보가 요청한 수보다 적게 나온다.** 변이 가능한 위치가 적거나 `최대 변이 수`가 작으면 서로 다른 서열을 요청한 수만큼 만들 수 없다. 로그에 경고가 남는다. 변이 수나 IBS 근처 반경을 키워 본다.
- **IBS 잔기가 바뀐 후보가 있나?** 없다. IBS 잔기는 항상 고정되고, Gly·Pro·Cys 위치도 바꾸지 않으며, 새 Cys도 넣지 않는다. 치환만 하며 길이는 시드와 같다.
- **실행이 실패했다.** 실행 이력 페이지의 오류 메시지와 로그를 본다. 대표 원인은 메모리 부족과 모델 파일 누락이며 `docs/ops.md`에 대처법이 있다.
