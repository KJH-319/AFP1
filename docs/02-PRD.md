# PRD: 부동 단백질(AFP) 디자인 앱 (슬림 v1)

작성일 2026-10-12 · 기준 문서: Claude Docs의 "PRD: 부동 단백질(AFP) 디자인 앱" 스냅샷

## 1. 개요

**AFP Designer는 연구자가 기존 부동 단백질(AFP)을 출발점으로 새 후보를 설계하고, 계산으로 순위를 매겨, 실험할 후보 목록까지 뽑는 연구실 내부용 웹앱이다.** v1은 의도적으로 작게 시작한다. 설계부터 평가까지 도구를 오가며 하던 수작업을 하나의 흐름으로 묶고, 그 순위가 쓸모 있는지는 소수 후보의 실험 결과로 확인한다.

**배경.** AFP는 얼음 결정 표면에 결합해 성장을 억제(열이력, Thermal Hysteresis)하고 재결정을 막는다. 냉동보존, 냉동식품, 저온 내성 작물에 쓰이지만 천연 AFP는 종류가 한정되고 활성, 안정성, 생산성이 최적이 아니다. 새 AFP를 설계하려면 서열 모델링, 얼음 결합면(IBS) 보존, 구조 예측, 평가를 서로 다른 도구에서 수작업으로 이어 붙여야 해서 후보 탐색 속도가 느리다.

**대상 사용자.** 단백질 공학 또는 냉동생물학 연구실의 소수 연구자가 사내 GPU 서버 또는 클라우드 GPU 위에서 사용한다. 외부 공개 서비스는 v1 범위가 아니다.

**제품 개념.** v1의 입력은 시드 AFP 하나다(내장 라이브러리, FASTA, PDB). IBS 잔기는 보존하고 나머지를 최적화해 후보를 만든 뒤, 구조 신뢰도, IBS 품질, 개발성을 평가해 순위표와 내보내기 파일을 낸다. IBS 모티프에서 시작하는 de novo 설계(모드 B), 간이 MD, 분류기 학습은 v1 이후(v1.x)로 미룬다.

## 2. 목표와 비목표

**v1의 목표는 "시드 → 설계 → 평가 → 내보내기"를 앱 하나에서 끝내는 것이다.** 실제 열이력(TH) 값을 정확히 예측하는 것은 목표가 아니다. v1은 작게 만들어, 점수 순위가 실험 결과와 맞는지를 가장 빨리 확인하는 데 쓴다.

**목표**

- 시드 AFP 기반 서열 최적화(모드 A)로 후보를 생성한다.
- 후보를 구조 신뢰도, IBS 품질, 개발성으로 자동 평가하고 단순 가중합으로 순위를 매긴다.
- 실험 검증용 후보(FASTA, PDB, CSV)를 내보낸다.
- 모든 실행의 시드, 도구 버전, 파라미터를 작업 폴더에 기록해 재현할 수 있게 한다.

**비목표 (v1 제외, v1.x에서 재검토)**

- IBS 모티프 기반 de novo 설계(모드 B)
- 간이 MD (얼음 슬랩 결합 시뮬레이션)
- 자체 AFP 분류기 학습
- 실험 결과 업로드와 점수 보정
- Pareto 순위, PDF 리포트
- TH 수치를 예측하는 회귀 모델
- 외부 사용자용 공개 서비스, 로컬 데스크톱 설치형 앱
- 작업 큐 서버, DB 서버 같은 별도 인프라

## 3. 사용자와 핵심 시나리오

| 페르소나 | 하는 일 | 앱에서 필요한 것 |
| --- | --- | --- |
| 설계 연구원 (주 사용자) | 후보를 설계·평가하고 실험할 서열을 고른다 | 시드 입력, 순위표, 3D 비교, 내보내기 |
| 연구실 책임자 | 후보 선정과 실험 투자 여부를 결정한다 | 순위표 요약, 점수의 한계 표기 |
| 시스템 관리자 | GPU 서버와 도구 환경을 운영한다 | 설치 검증, 작업 상태, 로그 |

**시나리오 1 — 기존 AFP 개선.** 연구원이 Type III AFP 구조를 시드로 고르고 IBS 잔기를 고정한 채 후보 100개를 생성한다. 앱이 평가를 마치면 상위 10개를 순위표로 보여주고, 연구원은 3D로 IBS를 비교한 뒤 상위 5개를 FASTA로 내보낸다.

**시나리오 2 — 새 시드 등록.** 연구원이 PDB 또는 FASTA 파일과 IBS 잔기 번호를 입력해 시드로 저장하고, 같은 흐름으로 설계를 실행한다.

**v1 이후 시나리오.** IBS 모티프에서 시작하는 de novo 설계(모드 B)와, 실험 결과를 CSV로 올려 점수 순위와 실측값의 상관을 확인하는 흐름은 v1.x에서 다룬다.

## 4. 기능 요구사항

v1은 17개 요구사항 중 P0 10개와 P1 3개를 구현하고, P2 4개(F-4, F-6, F-14, F-16)는 v1.x로 미룬다.

| ID | 요구사항 | 우선순위 | 수용 기준 |
| --- | --- | --- | --- |
| F-1 | 실행 기록 관리 | P0 | 실행마다 입력, 파라미터, 결과가 작업 폴더에 저장되고 다시 열 수 있다 |
| F-2 | 시드 AFP 라이브러리 | P0 | Type III, 곤충 TmAFP 등 3~5개가 IBS 잔기 주석과 함께 들어 있고 항목을 추가할 수 있다 |
| F-3 | 입력 불러오기 | P0 | FASTA, PDB 업로드와 IBS 잔기 번호 입력을 지원하고 잘못된 형식은 오류 메시지를 띄운다 |
| F-4 | IBS 모티프 지정 (모드 B용) | P2 | v1.x. 잔기 패턴, 길이, 접힘 토폴로지를 입력하고 형식 검사가 통과해야 실행된다 |
| F-5 | 모드 A: 서열 기반 최적화 | P0 | IBS 잔기는 고정하고 그 외 위치만 변이시키며 후보별 변이 목록을 보여준다 |
| F-6 | 모드 B: de novo 설계 | P2 | v1.x. backbone 생성, 서열 설계, 재예측을 한 번의 실행으로 연결한다 |
| F-7 | 구조 품질 검사 | P0 | ESMFold로 후보를 예측해 pLDDT와 시드 대비 RMSD를 계산하고 사용자가 임계값을 바꿔 필터링할 수 있다 |
| F-8 | IBS 지표 | P0 | 평면성, 결합면 면적, 격자 간격 정합, 소수성 비율을 후보별로 출력한다 |
| F-9 | AFP 유사도 점수 | P1 | 시드 대비 ESM-2 로그우도 변화와 서열 동일도를 표시한다. 분류기 학습은 하지 않는다 |
| F-10 | 중복 제거와 개발성 필터 | P1 | 서열 클러스터링으로 중복을 제거하고 순전하, pI, 소수성 패치, 글리코실화·절단 모티프를 플래그로 표시한다 |
| F-11 | 종합 점수와 순위표 | P0 | 단순 가중합이며 슬라이더로 가중치를 바꾸면 순위가 즉시 바뀌고, "실제 TH를 예측하지 않는다"는 문구가 항상 보인다 |
| F-12 | 3D 뷰어 | P1 | 후보와 시드를 겹쳐 비교하고 IBS 잔기를 강조 표시한다 |
| F-13 | 백그라운드 작업 실행 | P0 | 설계와 구조 예측이 UI를 막지 않도록 서브프로세스로 실행하고 진행률, 로그, 취소를 제공한다 |
| F-14 | 간이 MD | P2 | v1.x. 상위 K개를 골라 얼음 슬랩 시스템을 자동 구성하고 결합 지속 시간을 보고한다 |
| F-15 | 내보내기 | P0 | FASTA, PDB, CSV 순위표를 내려받는다 |
| F-16 | 실험 결과 업로드 | P2 | v1.x. CSV를 올리면 예측 점수와 실측값의 상관을 보여준다 |
| F-17 | 재현성 기록 | P0 | 시드, 도구 버전, 파라미터를 JSON으로 저장하고 같은 설정으로 재실행할 수 있다 |

## 5. 비기능 요구사항

**장시간 GPU 작업을 UI와 분리하고, 모든 결과를 재현 가능하게 기록하는 것이 가장 중요한 비기능 조건이다.** 아래 수치는 제안값이며 M0에서 하드웨어를 확정한 뒤 조정한다.

| 범주 | 요구사항 |
| --- | --- |
| 아키텍처 | 설계와 구조 예측 같은 무거운 작업은 UI 프로세스 밖의 서브프로세스로 실행하고, UI는 작업 폴더의 상태 파일(JSON)을 읽어 진행률을 보여준다. Streamlit의 재실행 모델 때문이다. 별도 큐 서버나 DB 서버는 쓰지 않는다 |
| 응답성 | 저장된 순위표 열기와 필터·정렬은 후보 1,000개 기준 2초 이내 (제안값) |
| 재현성 | 실행마다 난수 시드, 도구·모델 버전, 파라미터를 작업 폴더의 JSON에 기록하고 같은 설정으로 재실행할 수 있다 |
| 확장성 | 외부 도구 호출은 한 모듈에 모아 두고, 같은 역할의 도구가 둘 이상 필요해질 때 추상 인터페이스를 만든다 |
| 자원 관리 | GPU 동시 실행 수를 제한하고 같은 입력의 구조 예측 결과는 캐시한다 |
| 보안 | 사내 네트워크 또는 VPN 안에서만 접속하고 업로드된 서열·구조는 외부 서비스로 보내지 않는다. 예외는 사용자가 명시적으로 켜는 온라인 예측 API뿐이다 |
| 라이선스 | v1은 오픈 라이선스 도구를 우선 쓰고, Rosetta와 FoldX는 쓰지 않는다. 설치 시 도구별 라이선스를 확인한다 |
| 신뢰성 표기 | 모든 점수 화면에 "우선순위 보조 지표이며 실제 TH 예측이 아니다"를 표시한다 |
| 운영 | 작업 실패 시 원인 로그를 UI에서 볼 수 있고, 도구 설치 검증(smoke test)을 한 명령으로 실행할 수 있다 |

## 6. 성공 지표와 출시 기준

**v1이 성공했는지는 양성 대조를 스코어가 구분하는지와, 실험으로 넘긴 후보에서 활성이 나왔는지로 판단한다.** 목표값은 모두 제안이며 연구실과 합의해 확정한다.

| 지표 | 목표 (제안) | 측정 방법 |
| --- | --- | --- |
| 양성 대조 재현 | 알려진 AFP(Type III, TmAFP)가 비-AFP 대조보다 IBS 지표와 종합 점수에서 높다 | 양성 대조 테스트 스위트 |
| 설계 후보 품질 | 모드 A 후보 중 pLDDT 80 이상이면서 시드 대비 RMSD 2 Å 이하인 후보가 생성분의 30% 이상 | 고정 시드 회귀 테스트 |
| End-to-end 완주 | 시드 선택에서 내보내기까지 수동 개입 없이 완료 | UI 시나리오 테스트 |
| 실험 적중 | 실험한 상위 후보 5~10개 중 최소 1개가 IRI 또는 TH 활성을 보인다 | 실험 결과 (앱 밖에서 기록) |
| 사용성 | 신규 연구원이 설명서 없이 시나리오 1을 완료한다 | 사용자 관찰 테스트 |

**출시 기준 (v1.0)**

- [ ] P0 요구사항 10개가 모두 수용 기준을 통과한다.
- [ ] 양성 대조 재현 테스트가 통과한다.
- [ ] 시나리오 1과 2를 중단 없이 완주하고, 동일 설정으로 재실행하면 결과가 재현된다.
- [ ] 도구 설치 검증과 운영 문서가 준비되어 있다.
- [ ] 점수 한계 표기와 라이선스 확인이 끝나 있다.

## 7. 시스템 개요와 기술 스택

**시스템은 Streamlit UI, Python 서비스 계층, 별도 서브프로세스로 나눠 UI가 장시간 계산에 막히지 않게 하고, 별도 큐 서버나 DB 없이 작업 폴더 하나로 상태를 관리한다.**

```
[Streamlit / Gradio UI]   입력 · 순위표 · 3D 뷰어 · 진행률
          │
[서비스 계층 (Python)]    파이프라인 호출 · 결과 취합
          │   작업 요청 / 진행률은 상태 파일로 확인
[백그라운드 실행 (서브프로세스)]
     ├─ 설계      모드 A 서열 최적화 (IBS 고정, ESM 변이 제안)
     ├─ 평가      구조 QC · IBS 지표 · AFP 유사도 · 개발성 필터
     └─ 내보내기  FASTA · PDB · CSV
          │
[공통 기반]  작업 폴더(JSON 상태·파라미터, PDB·FASTA·CSV)  /  도구 환경(conda)
```

v1 이후: 모드 B de novo, 간이 MD, 분류기 학습은 모듈로 추가한다.

| 영역 | 선택 | 비고 |
| --- | --- | --- |
| UI | Streamlit (대안: Gradio), 3D 뷰어는 py3Dmol | 구현은 Streamlit으로 확정(stmol은 의존성 충돌로 제외) |
| 작업 실행 | Python subprocess + 작업 폴더의 JSON 상태 파일 | 사용자가 늘면 RQ 검토 |
| 저장소 | 파일시스템(작업별 폴더) | 이력 검색이 필요해지면 SQLite 추가 |
| 서열 설계 | ESM-2(변이 점수), 필요 시 ProteinMPNN(고정 잔기 지정) | IBS 잔기 고정 지원 |
| 구조 예측 | ESMFold(기본), ColabFold(선택) | MSA 없이 빠르게 실행 |
| 분석 | Biopython(구조 파싱·SASA), numpy | IBS 지표. 중복 제거는 해밍 거리(치환만 지원하므로 MMseqs2는 v1에서 쓰지 않음) |
| 배포 | conda 환경 하나, 사내 GPU 서버 1대 또는 클라우드 GPU | GPU 사양은 오픈 이슈 |
| v1 이후 | RFdiffusion, GROMACS 또는 OpenMM, TIP4P/Ice | 모드 B와 간이 MD를 추가할 때 도입 |

## 8. 데이터 요구사항과 점수 방법

**v1에 필요한 데이터는 큐레이션한 시드 3~5개와 양성 대조용 비-AFP 서열뿐이며, 분류기 학습 데이터와 TH 회귀 데이터는 v1.x로 미룬다.**

| 데이터 | 내용 | 출처 | 요구 사항 |
| --- | --- | --- | --- |
| 시드 AFP 라이브러리 | v1은 Type III, 곤충 TmAFP 등 3~5개. 이후 Type I·II·IV, AFGP, 식물/박테리아 DUF3494까지 20~30개로 확장 | PDB, UniProt | 항목마다 IBS 잔기 주석을 문헌과 구조로 수동 검증한다. PDB ID는 구현 시 실제로 확인한다 |
| 음성 대조 | 길이·조성이 맞춰진 비-AFP 서열과 구조 소수 | UniProt, PDB | 양성 대조 테스트에서 IBS 지표의 변별력을 확인하는 데 쓴다 |
| 실험 결과 (v1.x) | 후보별 IRI 또는 TH 측정값 | 연구실 실험 | CSV를 업로드하고 후보 ID와 연결한다 |

**점수 방법.** v1은 모델을 새로 학습하지 않는다. AFP 유사도는 시드 대비 ESM-2 로그우도 변화와 서열 동일도로 계산하고, 필요하면 공개 AFP 예측기를 참고용으로 붙인다. 분류기 학습(서열 유사도 30% 분리 평가 포함)과 TH 회귀는 공개 정량 데이터가 적어 v1.x 이후로 미루고, 실험 결과가 쌓이면 점수와의 상관부터 확인한다.

## 9. 마일스톤

**슬림 v1은 4단계(M0~M3)를 순차로 진행해 약 5~7주가 걸린다.**

| 단계 | 내용 | 기간 |
| --- | --- | --- |
| M0 | 환경 구축과 시드 큐레이션: 도구 smoke test, 시드 3~5개 | 1주 |
| M1 | 모드 A와 구조 QC: 시드 → 후보 → pLDDT 필터를 스크립트와 최소 UI로 end-to-end | 2~3주 |
| M2 | IBS 지표와 순위표 UI: IBS 지표, 개발성 필터, 종합 점수, 3D 뷰어 | 1~2주 |
| M3 | 검증과 내보내기: 양성 대조 검증, 내보내기, 문서화, 후보를 실험팀에 전달 | 1주 |
| v1.x | 모드 B de novo, 간이 MD, 분류기 학습, 실험 결과 업로드 | 일정 미정 |

M1(모드 A와 구조 QC)이 2~3주로 가장 길다. 모드 B(de novo), 간이 MD, 분류기 학습, 실험 결과 업로드는 v1 후보의 실험 결과를 본 뒤 우선순위를 다시 정한다. 시작일은 GPU 환경이 확정된 뒤 정한다.

## 10. 리스크, 가정, 의존성

**가장 큰 리스크는 in silico 점수가 실제 열이력(TH)과 어긋나는 것이며, v1을 작게 만들어 소수 후보를 실험으로 먼저 검증하는 것으로 대응한다.**

| 리스크 | 대응 |
| --- | --- |
| 점수와 실제 TH의 불일치 | 점수를 우선순위 표시로만 쓰고, v1 후보를 실험으로 확인한 뒤 v1.x에서 점수를 보정한다 |
| 반복·저복잡도 AFP를 ESM/AlphaFold가 잘 다루지 못함 | 곤충 β-helix 등은 pLDDT 임계값을 조절할 수 있게 하고 시드 대비 RMSD로 보완한다 |
| 범위가 다시 커짐 | P2 항목(F-4, F-6, F-14, F-16)은 v1 후보의 실험 결과를 본 뒤에만 착수하고, 착수 시 MD 비용과 설정 난이도를 다시 평가한다 |
| 도구 라이선스 | v1은 오픈 라이선스 도구만 쓰고 설치 시 라이선스를 확인한다 |
| Streamlit의 장시간 작업 한계 | 서브프로세스와 상태 파일 폴링으로 UI와 계산을 분리한다 |
| 생물안전·이중용도 | AFP는 위험도가 낮지만 기관 정책을 따르고 실행 로그를 보관한다 |

**가정**

- 사용자는 소수이며 동시 작업이 많지 않다.
- 실험 팀이 상위 후보를 발현·측정할 수 있다.
- 시드 AFP의 IBS 잔기를 문헌과 구조로 확인할 수 있다.

**의존성**

- GPU 서버 또는 클라우드 GPU 접근 (사양 미정)
- ESM-2, ESMFold(ColabFold는 선택)의 설치와 모델 가중치 다운로드
- PDB, UniProt 공개 데이터 접근

## 11. 오픈 이슈

구현에 착수하기 전에 다섯 가지를 정해야 하며, 그중 GPU 사양이 도구 범위와 일정을 좌우한다.

- [ ] **GPU 환경**: 로컬 GPU 모델과 VRAM, 또는 클라우드 사용 여부. ESMFold 실행 가능 여부와 일정이 여기에 달려 있다.
- [ ] **주 타깃 AFP 유형과 응용**: 냉동보존, 식품, 작물 중 무엇이 우선인지. v1 시드 3~5개를 무엇으로 할지 정한다.
- [ ] **UI 프레임워크**: Streamlit과 Gradio 중 최종 선택. 3D 뷰어와 다중 페이지가 중요하면 Streamlit을 권한다.
- [ ] **수치 목표 확정**: pLDDT 80, RMSD 2 Å, 생성분의 30% 등 성공 지표와 비기능 수치는 모두 제안값이다. 연구실과 합의가 필요하다.
- [ ] **v1.x 착수 조건**: v1 후보의 실험 결과가 어느 정도면 모드 B와 간이 MD로 넘어갈지 정한다.
